## 1. 位置づけ

`bi/model.py` と `bi/run.py` は、Power Pivot 版（M クエリ ⓪～⑪ とピボット）と同じ入力から同じ表を作る Python 版です。
ここに書いた定義が正解で、Power Pivot 版はこの出力と一致するように直していきます。

- 入力: 実績フォルダ（薬品使用量予測データ YYYYMM）、出納フォルダ（数量一覧）、手入力テーブル.xlsx
- 出力: `bi/out/モデル.xlsx`（全テーブル）、`bi/out/ダッシュボード.html`
- 実行: `python bi/run.py --tables tests/out_clinic/export/手入力テーブル.xlsx`

データモデルの表（T_日次・T_月次・M_日付・M_薬品・M_理由コード・T_判定理由）は、M クエリ ⑥～⑪ の定義をそのまま写しています（列名・計算式とも同じ）。

## 2. 0.2.0 で Power Pivot 側に足すもの

### 2.0 実績を参考にする期間と包装単位（0.4）

- 設定の 開始日・終了日 は廃止。① 設定値 が「終了日 ＝ 予測開始日（発注日の翌日）の前日 ＝ 発注日、開始日 ＝ 終了日の 1 年前の翌日が属する月の 1 日」と決める。予定（T_日次）も出納（⑤）もこの期間の月だけ読む（設定に行が残っていればその値を優先）。
- 包装単位（在庫情報の列・標準の包装単位）は廃止。箱で数える指標（1箱消化日数・直近の1箱消化日数・返品できる箱数・S03）は使わない。極小需要の線は「極小需要の月の払出」（初期値 100）の 1 本にし、E の対象、G02 の「ほとんど出ない薬は除く」、A の持ち方の「回転」（直近の1日平均払出 × 30 ≧ 線）に使う。

### 2.1 M_薬品 に足す列（出納から）

| 列 | 定義 |
|---|---|
| 直近の払出合計 | 出納のある月のうち、新しい方から設定「直近の月数」（初期値 3）ヶ月の払出の合計 |
| 直近の1日平均払出 | 直近の払出合計 ÷ 直近の月の暦日数 |
| 直近の在庫日数 | 最終在庫 ÷ 直近の1日平均払出 |

理由: 全期間の平均（在庫日数）は、途中で需要が落ちた薬を隠す。
架空データでは、出荷調整で切り替わったセルトラリン25「アメル」が、全期間平均では在庫 18 日分、直近では 1,066 日分になった。

### 2.4 薬品グループの 切替先 と M_薬品 の切替の列（0.7）

手入力テーブル 薬品グループ の列は 薬品名／成分規格／需要のまとまり／先発後発／供給状況／切替先。
経過措置などで旧品の需要を新品に移すとき、**旧品の行**の 切替先 に新品の薬品名を書く（列がなければ切替なし）。旧品と新品は同じ 需要のまとまり に入れる。

| 列（M_薬品） | 定義 |
|---|---|
| 切替先 | 薬品グループの値。入っている薬（切替元）は 区分 ＝ D（これからの需要は切替先へ移る。T_ABC月次 は変えず M_薬品 で上書き） |
| 切替元 | この薬を 切替先 にしている薬。複数なら「、」でつなぐ |
| 切替元の在庫 | 切替元の最終在庫の合計 |
| まとまりの直近1日平均払出 | 同じ 需要のまとまり の薬すべての 直近の1日平均払出 の合計。未登録なら自分の値 |
| 切替の使い切り日数 | 切替元の 最終在庫 ÷ まとまりの直近1日平均払出（切替先の需要で使い切る見込み）。払出が 0 なら空欄 |

返品は区分とも切替とも無関係（返せる在庫は返す）。発注の収束（まとまりの発注を 1 つの屋号に寄せる：切替先があればそれ、なければ 通常供給で直近の払出が最多の屋号）は 0.7・0.8 には入れず、0.9 で入れた（2.6 と R5）。

### 2.6 発注の収束：M_薬品 の 発注先 とまとまりの列（0.9）

利用者の依頼（2026-11-08）：「予測使用量の計算で、複数の品目が出てきており、グルーピング済みの品目であった場合の処理分岐を実装。需要量を合算し、発注量を算出」。
薬品グループ で同じ 需要のまとまり に 2 つ以上の薬（屋号）があるときだけ、R5 はその予定・在庫を合算して 発注先 の 1 薬に寄せる（R5 を参照）。登録のない薬・1 つだけの薬はこれまでどおり薬ごと。

| 列（M_薬品） | 定義 |
|---|---|
| 発注先 | まとまりの発注を寄せる薬。誰かの 切替先 になっている薬 → なければ、切替先なし・供給状況が空欄か「通常」・発注除外でない・経過措置でない薬のうち 直近の払出合計 が最多の薬 → それもなければ、切替先なしで 直近の払出合計 が最多の薬。同点は薬品名順。1 つだけ・未登録なら空欄 |
| まとまりの品目数 | 同じ 需要のまとまり に登録されている薬の数。未登録なら 1 |
| まとまりのずれの割合 | まとまり全体の（払出 − 予定）÷ 予定 ＝ Σ比較のずれ合計 ÷ Σ比較の予定合計（まとまりの薬すべて）。未登録なら自分の ずれの割合。切替で払出が旧品・予定が新品に分かれていても、まとまりとして正しく出る |
| 比較の予定合計 | ずれの割合 の分母（出納と予定の両方がある月の予定の合計）を列として出したもの |
| 比較のずれ合計 | ずれの割合 の分子（同じ月々の 払出 − 予定 の合計）を列として出したもの |

区分（T_ABC月次。まとまりごと。切替元は D）、理由コード、R1～R4 は 0.9 では変わらない。Python 版は `bi/model.py` の `_m_drug` に同じ列、`bi/run.py` の `r5_order()` に同じ合算。

### 2.7 傾向（0.10）

利用者の決定（2026-11-08）：「予測は予測、実績をなるべく重きをおいて集計し、直近 3 ヶ月 vs その前 3 ヶ月 vs 年間の形で、傾向を分析し、発注量の調整をユーザーに委託する形が良い」（同じ相談の中で「増加傾向、減少傾向の傾向分析は、直近と年間の期ごとの動きの動態変化から予測する形にはしたい」）。
傾向は出納（実績）を主にして計算し、理由を付けて表示する（M_薬品、R1、R5、D07／D08）。**発注の目安の計算は変えない**（R5：来週の予定 × (1 ＋ 年間のずれ) − 在庫 のまま）。増やすか減らすかの判断と量の調整は使う人が行う。

N ＝ 設定「直近の月数」（3）。3 つの期間 ＝ 直近 N ヶ月（出納のある月の新しい方から）、その前の N ヶ月、年間（出納のある月すべて）。それぞれの 1 日平均払出（払出の合計 ÷ 暦日数）で比べる。

| 列（M_薬品） | 定義 |
|---|---|
| 前の払出合計 | 直近 N ヶ月の前の N ヶ月の払出の合計 |
| 前期比 | 直近の1日平均払出 ÷ 前の N ヶ月の1日平均払出（前の期の払出が 0 なら空欄） |
| 年間比 | 直近の1日平均払出 ÷ 1日平均払出（年間。出納のある月すべて） |
| 傾向 | 月不足 ＝ 出納の月が 2N ヶ月に足りない ／ 少量 ＝ 月平均払出 ＜ 極小需要の月の払出（100。まばらな薬は判定しない）／ 増加 ＝ 前期比・年間比とも 1 ＋ 傾向の線（0.2）以上 ／ 減少 ＝ とも 1 − 線 以下 ／ 横ばい ＝ それ以外。前の期の払出が 0 で直近に払出があれば 増加 |
| まとまりの前期比／まとまりの年間比／まとまりの傾向 | 同じ 需要のまとまり の薬の払出を合算して同じ見方をしたもの。未登録なら自分の値。切替で払出が旧品から新品に移っていても、まとまりとしては 横ばい になる |
| 前の月平均患者数／年間の月平均患者数 | 予定データのある月の、予定の延べ患者数の月平均。窓は「ABCの月数」（3）：直近（0.5 からある 直近の月平均患者数）、その前の同じ月数、年間 |
| 患者の前期比／患者の年間比／患者の傾向 | 患者数で同じ見方。少量 ＝ 年間の月平均患者数 ＜ 区分Dの患者数（2）、月不足 ＝ 予定の月が 2 × ABCの月数 に足りない。払出の 傾向 と見比べて「患者が減った」か「用量が変わった・来なくなった分」かを分ける |
| 直近のずれの割合 | 直近 N ヶ月だけの（払出 − 予定）÷ 予定（出納と予定の両方がある月）。来なくなった患者の分は年間の ずれの割合 より先にここに出る |

- 理由コード D07（増加）・D08（減少）は薬自身の 傾向 から付ける（2.2）。
- R1 と R5 に出す列と文言は 3 章。R5 の列 傾向 は 増加／減少 のときだけ出し、まとまりで合算している薬は まとまりの傾向 を使う。
- 設定 傾向の線 0.2 は仮の値。実データで M_薬品 の 前期比・年間比 の分布と、増加／減少 が付いた薬を見て直す（区分の線と一緒に）。
- Python 版：`bi/model.py` の `_m_drug` に同じ列、`REASON_CODES` に D07／D08、`_reasons`。`bi/run.py` の `r1_abc`（傾向・年間比・患者の傾向）と `r5_order()`（傾向 の列と注意）。`DEFAULTS` に 傾向の線 0.2。

## 3. レポートの定義

### R1 ABC 区分表（0.5 で区分 A／B／C／D に）

- 単位: 薬品グループの「需要のまとまり」。未登録の薬は薬品名単体。
- 窓: 出納のある月のうち直近「ABCの月数」ヶ月。その月までに出納か予定に一度でも出たまとまりは、窓に払出がなくても行を持つ（払出 0）。
- 月平均払出: 窓の払出のまとまりでの合計 ÷ 窓の月数（錠／月）。
- 量の区分: 月平均払出 ≧ 区分Aの線（1000）→ A、≧ 区分Bの線（300）→ B、それ未満 → C（0 も C）。固定の線なので、他の薬の増減で自分の区分は動かない。
- 患者の最少月: 窓の各月のうち予定データのある月について、まとまりの予定の延べ患者数（T_月次 の予定患者数をまとまりで合計。予定の行がない月は 0 人）を取り、そのいちばん少ない月の値。窓に予定データの月が 1 つもなければ空欄。月平均患者数は同じ月々の平均（参考）。
- 区分: 患者の最少月 ＜ 区分Dの患者数（2）→ D（量より優先。出納だけの薬は患者 0 なので D）。患者の最少月が空欄なら 量の区分。それ以外は 量の区分。
- 意味: A ＝ 一度に全量を発注できないほど需要が多い薬（在庫の上限を人が管理）、B ＝ 通常の発注量でよい薬、C ＝ 定期処方はあるが量は多くない薬、D ＝ 予定の患者が極端に少なく在庫を手で管理する薬。区分は持ち方を決めるだけで、返品・転送は区分と無関係。
- 構成比・累積: 窓の払出の構成比と累積。参考として残す（0.4 までの区分の根拠。区分には使わない）。
- 前月の区分: 終わりの月を 1 ヶ月前にずらして同じ計算。変更 = 「B→A」のように表示（変更なし）。
- 列: 需要のまとまり／薬品名／略称／先発後発／直近の払出／月平均払出／量の区分／患者の最少月／構成比／累積／今月の区分／前月の区分／変更／在庫日数／需要の型／最終在庫／傾向／年間比／患者の傾向（0.10）
- 傾向・年間比・患者の傾向（0.10）: M_薬品 の まとまりの傾向・まとまりの年間比 と、代表の薬 の 患者の傾向（2.7）。Power Pivot 版 ⑮ A 表では 変化 の右に置く（Python 版 `r1_abc`）。増加／減少 なら 理由 に「増加傾向（年間の n%。患者は …）」と書く。載せる条件（区分変更、または 変化 ≧ 発注点見直しの変化）は変えない。`excel_format.ps1` で 増加 赤・減少 青（変化 と同じ色）。
- 月ごとの区分（T_ABC月次: 月×まとまり。列に 月平均払出・量の区分・患者の最少月・月平均患者数・区分・前月の区分・変更）も持ち、区分の安定性（K0 の ABC変更数）に使う。`bi/run.py` の `abc_monthly()` は `model.T_ABC月次` をそのまま返す。
- 線の初期値 1000／300／2 は仮の値。実データで M_薬品 の 月平均払出 と 直近の月平均患者数 の分布を見て決め直す。

### R2 不動薬の処理候補

- 対象: S01・S02・S05・S06 のいずれかが付いた薬。0.7 から、切替先 が入っている薬（切替元）も在庫 > 0 なら載せる。
- 余った量 = max(0, 最終在庫 − 直近の1日平均払出 × 当面の予定日数)。
- 列: 薬品名／略称／棚番／最終在庫／最後に動いた月／動きのない月数／在庫日数／直近の在庫日数／直近の1日平均払出／余った量／需要のまとまり／警告（S コードの文言）
- 並び: 動きのない月数の多い順、次に在庫日数の多い順。
- Power Pivot 版の B 表（⑯）: 種類 ＝ 不動／切替中／在庫過多（0.6.1 で「区分」から改名。区分 の列は M_薬品 の A／B／C／D）。切替元は 不動 とせず「切替中」とし、処置の案は「切替先「新品」の需要で使い切る（見込み N日）。返品できる分は返品」（N ＝ 切替の使い切り日数の切り上げ）。並びは 不動 → 切替中 → 在庫過多（`excel_format.ps1` で 不動 赤、切替中 黄色）。

### R3 経過措置・期限切迫

- 対象: 経過措置リストにある薬。
- 残り日数 = 経過措置期限 − 基準日（設定「発注日」）。期限切迫 = 残り日数 ≦ 期限切迫の日数。
- 期限までに使い切れる量 = 1日平均払出 × max(0, 残り日数)。余る量 = max(0, 最終在庫 − 使い切れる量)。
- 列: 薬品名／略称／経過措置期限／残り日数／期限切迫／最終在庫／1日平均払出／期限までに使い切れる量／余る量／警告（E01・E02）
- 並び: 残り日数の少ない順。
- 0.7 から: 代替の屋号 ＝ 薬品グループの 切替先 があればそれ、なければ同じ 需要のまとまり で経過措置のない薬（後発を優先、直近の払出の多い順）。切替先 が入っている薬の 1日平均払出 には まとまりの直近1日平均払出 を使う（旧品自身の払出は 0 に近いため）。使い切れる量・余る量もその値で計算する。

### R4 出荷調整の可能性

- G01: まとまり内の屋号ごとの月次構成比を出し、前月比の変化が線以上の屋号を月とともに出す。
- G02: 2.2 の条件。
- 列: 需要のまとまり／薬品名／月／コード／前月の構成比／当月の構成比／変化／まとまりの払出_前月／まとまりの払出_当月／理由
- 並び: 月の新しい順。

### R5 発注書（来週の分。0.6 で追加、0.9 でまとまりの合算、0.10 で傾向の列。Power Pivot 版は ㉔ R_発注書 → シート F_発注書）

週 1 回、発注する日に 発注日 を合わせて作る。`bi/run.py` の `r5_order()`（出力シート `R5_発注書`）。1 行 1 薬。

- 来週: 予測開始（発注日の翌日）～予測終了（予測開始 ＋ 予測日数 − 1。初期値 7 日）。
- 来週の予定・来週の患者: 予測データ（薬品使用量予測データ。予測フォルダパス、空欄なら実績フォルダ）の来週の 予定使用量・患者数 の合計。当月の予測データには月末までの予定が入っている。来週が翌月にかかるときは翌月のファイルも置く。
- 在庫: 予測データの一番新しい日の 在庫数量（発注残を含む）。予測データに出ない薬は M_薬品 の最終在庫（出納の最終月。月単位なので参考）。
- ずれ: M_薬品 の ずれの割合（1 年の 払出 ÷ 予定 − 1。空欄は 0）。見込み = 来週の予定 × max(0, 1 ＋ ずれ)。
- 不足 = max(0, 来週の予定 − 在庫)。発注の目安 = max(0, 見込み − 在庫) の切り上げ（錠。箱への切り上げは現場）。判定が「発注しない」なら 0。
- 必要な最大在庫: 1 年の日次の予定（T_日次）を「次の納品日」でまとめる。ある日の注文はその次の卸の営業日（④ fx_卸の休み：土日・祝日・年末年始・追加休業日を除く）に届くとし、同じ納品日になる日々を 1 つの区切りにして 予定数量 を合計、その最大 × max(0, 1 ＋ ずれ)。最大の期間 = その区切りの 最初の日～最後の日（日数）。連休をまたいでも不足しない在庫の上限の目安（区分 A の薬を人が管理するための数字）。棚の容積は入れない。
- まとまりの合算（0.9。発注の収束）: 薬品グループ で同じ 需要のまとまり に 2 つ以上の薬があるとき（M_薬品 の 発注先 が入っている薬）、まとまりの予定 ＝ まとまりの 来週の予定 の合計、まとまりの在庫 ＝ まとまりの 在庫 の合計。見込み・不足・発注の目安・必要な最大在庫（と 上限を超える）は この合計で計算し、ずれ には M_薬品 の まとまりのずれの割合 を使って、**発注先の行にだけ**出す。ほかの屋号の行は 判定「寄せる」、発注の目安 0、不足・見込み・必要な最大在庫・最大の期間 は空欄（在庫は使い切る）。屋号ごとの 来週の予定・来週の患者・在庫 の列はその薬自身の値のまま。登録のない薬・1 つだけの薬は薬ごとに計算する（0.6 のまま）。合算している切替（旧品と新品が同じまとまり）では、切替先（＝発注先）に「控えめに」を付けない（切替元の在庫は合算した在庫に入っている）。
- 傾向（0.10）: 列 傾向 ＝ M_薬品 の 傾向（合算している薬は まとまりの傾向）が 増加／減少 のときだけその値（横ばい・少量・月不足 は空欄）。注意に「減少傾向（直近 N ヶ月は前の N ヶ月の a%、年間の b%。患者は <患者の傾向>）。目安を減らすか検討」／「増加傾向（…）。目安を増やすか検討」（a ＝ 前期比 × 100、b ＝ 年間比 × 100。患者の傾向 が空欄なら「不明」）。**発注の目安の計算は変えない**（上の式のまま）。増減の判断と量の調整は使う人が行う（2.7）。
- 判定: 発注しない = 発注除外、または 供給状況 が 供給停止・薬価削除予定、または 切替元（薬品グループの 切替先 あり。0.7）。寄せる = まとまりの発注先でない屋号（0.9。目安 0）。控えめに = 区分 D／経過措置品／供給状況 限定／ずれ ≦ −ずれの注意割合／切替先（0.7。合算していないときだけ）のどれかで、目安 > 0。発注する = それ以外で 目安 > 0。不要 = 目安 0。経過措置品は「発注しない」ではなく「控えめに」。
- 注意（「、」でつなぐ）: 発注除外／供給停止・薬価削除予定／限定出荷／出荷調整の疑い（T_まとまり月次 の一番新しい月の G01・G02）／期限の近いロットを先に使う（T_ロット の 残り日数 ≦ 期限切迫の日数 か 返す量 > 0）／予定より n% 少なく出る／患者が少ない（区分 D）／経過措置品（切替先があれば発注しない）／予定にない薬（出どころ が 出納だけ）／上限を超える（区分 A で 在庫＋目安 ＞ 必要な最大在庫）／切替元（「新品」へ寄せる。在庫を使い切る）／切替先（切替元の在庫 N を使い切るまで控えめに）（0.7。合算していないとき）／切替元（在庫を使い切る）／切替先（切替元の在庫は合算済み）（0.9。合算しているとき）／まとまり「G」の発注先（n 品目の 予定 P・在庫 S を合算）／「発注先」に寄せる（まとまり「G」：予定 P・在庫 S を合算）（0.9）／減少傾向（直近 N ヶ月は前の N ヶ月の a%、年間の b%。患者は …）。目安を減らすか検討／増加傾向（…）。目安を増やすか検討（0.10）。
- 載せる行: 来週の予定 > 0、不足 > 0、注意あり のいずれか、または 区分 A（常に）。合算している薬は まとまりの予定・まとまりの不足 で見て、合算の注意（発注先・寄せる）だけでは載せない。載るときはまとまりの屋号がそろって載る（0.9）。傾向の注意だけでも載せない（0.10）。
