## 1. 目的と範囲

毎月、出納と予測データ（＋システムの追加リスト）を読み込むだけで、次の 5 つの判断が紙 1 枚ずつで済む状態にする。

| 区分 | 判断 | 対応するクエリ |
|---|---|---|
| A | 発注点の切り替え（区分や払出が動いたまとまり） | R_発注点見直し |
| B | 不動在庫の返品・転送 | R_不動在庫 |
| C | 経過措置・期限切迫品の処理 | R_経過措置 |
| D | 出荷調整（推奨・次点ジェネリックの切替と在庫転送） | R_出荷調整管理票 |
| E | 極小需要薬を持つか取り寄せるか | R_極小需要 |

正解は Python 版（`bi/model.py`・`bi/run.py`・`bi/report.py`、定義は `docs/月次レポート定義.md`）。
Power Pivot 版は同じ入力から同じ数字が出ることを受け入れ基準にする。

範囲外: 日々の発注（PowerQuery_ABC）、DAX メジャー（使わない方針）、ロットの使用期限（追加リストが来るまで）。

### 2.4 読めるファイルの形式（0.4.0）

背景: 店の実データで 1 つのファイルも読めていないことが分かった。0.3.0 までの Excel での確認は .xlsx の架空データだけで、.xls は一度も Excel で動かしていなかった。
.xls では数値も日付も「画面に表示されている文字」で届くが、② の数値への変換が文字で届いた数値をすべて空にしていた（7.1）。
.xls は不具合が出やすいので、.csv と .txt にも対応する。

要件:
- 読める形式は .xls／.xlsx／.csv／.txt（タブ区切りの .tsv も可）。同じフォルダに混ざっていてもよい。
- ファイルは拡張子ではなく中身で見分ける（先頭の数バイトで .xls／.xlsx を判定し、どちらでもなければ文字のファイル）。開くのは必ず ㉒ fx_ファイルを開く を通す。
- 文字のファイルは、文字コード（UTF-8 の BOM あり・なし／UTF-16／Shift_JIS）と区切り（カンマ・タブ。先頭 50 行で多い方）を自動で見分ける。列の数は一番長い行に合わせ、値はすべて文字、空欄は null で返す。
- 出納と 3 つのリストは、.xls のときと同じ見出しの名前で読む（「品名」のある行を見出しとして探す）。.xls はシートが名前の順に並んで届くので、「品名」の見出しがあるシートを選ぶ。出納の、見出しより上に書かれた期間の行は文字のファイルでも読む。
- 薬品使用量分析データを文字のファイルで置くときはシートがないので、次のどちらかの形だけ読む（どちらでもなければ読まない）。
  1. 見出しに「日付」の列がある（1 つのファイルに何日分あってもよい。見出しの名前「日付」は ① に固定）
  2. 1 日 1 ファイルで、ファイル名に 8 桁の日付がある（例: `薬品使用量分析データ20261010.csv`）
  - エリシアSがこの帳票を .csv で出したときの実際の並びは未確認。上の 2 つは仮の決まり（8 章）。
- 数値は、空白・桁区切り・円記号を外し、▲／△ をマイナスに直して読む。読めなければ先頭の数字の部分を使う（`1,234`・`100錠`・`¥9,801`・`▲50`・`12.5%`）。②⑤⑭⑳㉑ が対象。
- 日付は、日付のセル・`yyyy/mm/dd`・`yyyy-mm-dd`・`yyyy年m月d日`・8 桁の `yyyymmdd`・時刻つきの文字（`2026/10/01 09:00:00`）を読む。②⑭⑳㉑ が対象。
- 読めないファイルは黙って読み飛ばさない。空のファイル、中身が HTML・XML のファイル、開けないファイルは、ファイル名を付けたエラーにする（`[読めないファイル] 「ファイル名」を開けません：…`）。
  ⑤⑭⑳㉑ は、読む対象のファイルに「品名」の見出しがないときも、ファイル名を付けたエラーにする。② は「薬品名」の見出しがないシートだけ読み飛ばす。
- どのファイルが読めたか・読めなかったかは、㉓ 読込の確認（シート「読込の確認」）で分かること（4 章）。

.xls で気を付けること（Excel で確認、2026-11-07）:
- 長い数字が指数の表示（`4.99E+12` など）になっていると元に戻せない（JAN コードが危ない）。小数を丸めて表示している数値は丸めた値で届く。
- 非表示のシートは届かない。印刷範囲などの名前がシートのように混ざって届く（㉒ が外す）。
- エリシアSで .csv（または .txt）で出せる帳票は、そちらを使う方が確実。

### 4.1 M で書くときの注意
- 月の横持ち（月01…月12）は `Table.Pivot` ではなく、`List.Transform` で 12 ヶ月分の列を固定名で作る（ピボットは月が増えると列名が変わり、シートの書式が崩れる）。
- まとまり内の順位付けは `Table.Group` → グループ内で `Table.Sort` → `Table.AddIndexColumn`。大きな表に対する行ごとの `Table.SelectRows` は避ける（既存ルール）。
- 直近 N ヶ月の判定は「出納のある月」を `List.Distinct` → `List.Sort` → `List.LastN`。暦の月ではない。
- 設定は `Num("項目", 初期値)` で読む（既存の書き方）。新しい項目を設定表に足し忘れても初期値で動くこと。
- G02 の「ほとんど出ない薬（月の払出 < 極小需要の月の払出）は除く」を忘れない（箱単位の発注では仕入 0 の月が普通にある）。
- 文言の数値は `Number.ToText(Number.Round(x, 0), "N0", "ja-JP")`（既存どおり）。
- レコードの項目名や識別子に「・」「（）」「／」など英数字・下線・かな漢字以外の文字を使うときは `#"…"` で囲む（⑱ の `切替・転送の案` が Excel で解析エラーになった。`_tools/mcheck.py` が IDENT? で検出する）。
- エリシアSの出力ファイルは、必ず ㉒ fx_ファイルを開く を通して開く（ほかのクエリで直接 `Excel.Workbook` などを呼ばない）。
- .xls と文字のファイルでは数値も日付も文字で届く。数値・日付への変換は、文字で届いた場合（`1,234`・`100錠`・`2026/10/01 09:00:00` など）を必ず試す。
- `Text.Remove` に渡せるのは 1 文字ずつだけ（「mL」「cap」のような 2 文字以上を渡すとエラー）。エラーになりうる式を、文字の場合を試さないまま `try … otherwise null` の中に入れない（エラーが隠れて、値がすべて空になる。0.4.0 で直した不具合の原因）。

## 5. Excel 側（レポートの体裁）

- A〜E はそれぞれ 1 シート。クエリをテーブルとして読み込み、列幅・書式・条件付き書式はテーブルに付ける（更新しても残る）。
- グラフ: A と D の 12 ヶ月は Excel のスパークライン（縦棒）を月01…月12 の範囲に付ける。D の構成比はスパークライン（積み上げはできないので、推奨ジェネリックの構成比の折れ線で代替）。
- 印刷: 各シートを A4 横、1 ページ幅に収める（「すべての列を 1 ページに印刷」）、ヘッダーに対象月・基準日。
- 条件付き書式: 不動＝薄い赤、注意＝薄い橙（Python 版と同じ色分け）。
- 運用: 月初に「すべて更新」→ A〜E を印刷（または PDF）。

## 7. 検証手順と受け入れ基準

Excel 側の操作は `tools/`（自宅 PC 用。店の PC では使わない）で自動化する。試作ブックは `prototype/ABC分析.xlsx`（git 未追跡）。

**確認は .xlsx／.xls／.csv／.txt の 4 形式すべてで行う。** 店の実物は .xls で、.xls と文字のファイルでは数値も日付も文字で届くため、.xlsx だけでは不具合が見つからない（0.3.0 までは .xlsx だけで確かめていた）。「Excel で確認済み」と書くときは、確かめた形式を書く。

- 架空データ（4 形式）:
  1. `python tests/make_testdata.py` → `tests/out` に .xlsx（6 か月・14 品目、期待値は `tests/out/期待値.xlsx`。1000 以上の数値は桁区切りの表示。作り直すと `tests/out/形式別` も消える）
  2. `python tests/make_formats.py` → `tests/out/形式別/csv`（カンマ区切り・Shift_JIS、実績は 1 日 1 ファイル）と `tests/out/形式別/txt`（タブ区切り。実績は「日付」の列つきの月 1 ファイルで UTF-8（BOM あり）、出納は UTF-8（BOM なし）、リストは UTF-16）
  3. `pwsh -File tools\make_xls.ps1` → `tests/out/形式別/xls`（Excel を使って本物の .xls に変換。LibreOffice は要らない）
  4. `python tests/make_formats.py --check` → Python 版で .xls／.csv／.txt を組み立て、.xlsx のときと同じ結果か確かめる
- 導入: `pwsh -File tools\excel_install.ps1 -Book prototype\ABC分析.xlsx`（txt のクエリ 24 本を入れ、データモデル 9 表・シート A〜E・シート「読込の確認」・リレーションシップ 10 本を作って更新）。
- 許可: ブックを Excel で開き、[クエリのオプション]→[現在のブック]→[プライバシー]→「無視」を選び直して保存（クエリを書き換えたあとは許可が効かなくなり、Formula.Firewall のエラーになる）。
- 形式の切り替え: `pwsh -File tools\excel_install.ps1 -Book prototype\ABC分析.xlsx -SettingsOnly -Folder … -SuiFolder … -KigenFolder … -KeikaFolder … -FudoFolder …`（設定のフォルダだけを、その形式のフォルダに書き換えて保存する）。
- 書き出し: `pwsh -File tools\excel_dump.ps1 -Book prototype\ABC分析.xlsx`（M_薬品・T_月次・T_判定理由・T_ABC月次 を `tests/out_excel/` に CSV で。ブックは保存しない。Formula.Firewall が出たら `-Touch`。ほかのクエリは `-Queries 日次データ,出納,読込の確認` のようにカンマ区切りで渡す。渡したクエリだけが書き出される）。
- 形式ごとに「切り替え → 書き出し → 突き合わせ」を繰り返す。

### 7.1 小さい架空データ（`tests/out`）— 4 形式で一致済み
