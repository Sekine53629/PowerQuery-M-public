## 1. 位置づけ

`bi/model.py` と `bi/run.py` は、Power Pivot 版（M クエリ ⓪～⑪ とピボット）と同じ入力から同じ表を作る Python 版です。
ここに書いた定義が正解で、Power Pivot 版はこの出力と一致するように直していきます。

- 入力: 実績フォルダ（薬品使用量予測データ YYYYMM）、出納フォルダ（数量一覧）、手入力テーブル.xlsx
- 出力: `bi/out/モデル.xlsx`（全テーブル）、`bi/out/ダッシュボード.html`
- 実行: `python bi/run.py --tables tests/out_clinic/export/手入力テーブル.xlsx`

データモデルの表（T_日次・T_月次・M_日付・M_薬品・M_理由コード・T_判定理由）は、M クエリ ⑥～⑪ の定義をそのまま写しています（列名・計算式とも同じ）。

## 2. 0.2.0 で Power Pivot 側に足すもの

### 2.0 実績を参考にする期間と包装単位（0.4）

- 設定の 開始日・終了日 は廃止。① 設定値 が「終了日 ＝ 予測開始日（発注日の翌日）の前日 ＝ 発注日、開始日 ＝ 終了日の 1 年前の翌日が属する月の 1 日」と決める。予定（T_日次）も出納（⑤）もこの期間の月だけ読む（設定に行が残っていればその値を優先）。

### 2.1 M_薬品 に足す列（出納から）

| 列 | 定義 |
|---|---|
| 直近の払出合計 | 出納のある月のうち、新しい方から設定「直近の月数」（初期値 3）ヶ月の払出の合計 |
| 直近の1日平均払出 | 直近の払出合計 ÷ 直近の月の暦日数 |
| 直近の在庫日数 | 最終在庫 ÷ 直近の1日平均払出 |

理由: 全期間の平均（在庫日数）は、途中で需要が落ちた薬を隠す。
架空データでは、出荷調整で切り替わったセルトラリン25「アメル」が、全期間平均では在庫 18 日分、直近では 1,066 日分になった。

### 2.4 薬品グループの 切替先 と M_薬品 の切替の列（0.7）

手入力テーブル 薬品グループ の列は 薬品名／成分規格／需要のまとまり／先発後発／供給状況／切替先。
経過措置などで旧品の需要を新品に移すとき、**旧品の行**の 切替先 に新品の薬品名を書く（列がなければ切替なし）。旧品と新品は同じ 需要のまとまり に入れる。

| 列（M_薬品） | 定義 |
|---|---|
| 切替先 | 薬品グループの値。入っている薬（切替元）は 区分 ＝ D（これからの需要は切替先へ移る。T_ABC月次 は変えず M_薬品 で上書き） |
| 切替元 | この薬を 切替先 にしている薬。複数なら「、」でつなぐ |
| 切替元の在庫 | 切替元の最終在庫の合計 |
| まとまりの直近1日平均払出 | 同じ 需要のまとまり の薬すべての 直近の1日平均払出 の合計。未登録なら自分の値 |
| 切替の使い切り日数 | 切替元の 最終在庫 ÷ まとまりの直近1日平均払出（切替先の需要で使い切る見込み）。払出が 0 なら空欄 |

返品は区分とも切替とも無関係（返せる在庫は返す）。発注の収束（まとまりの発注を 1 つの屋号に寄せる：切替先があればそれ、なければ 通常供給で直近の払出が最多の屋号）は 0.7 には入れず、次の版で扱う。

### 2.5 薬品グループ案（0.7。レポートではなく、薬品グループ を作るための確認用の表）

Power Pivot 版は ㉕ 薬品グループ案 → シート「薬品グループ案」、Python 版は `bi/model.py` の `parse_drug_name()`／`propose_groups()` → `Model.薬品グループ案`（`bi/out/モデル.xlsx` にも出す）。M_薬品 の薬ごとに 1 行。

- 分解: 後発品の名前「成分名＋剤形＋規格「屋号」」を 成分・剤形・規格・屋号 に分ける。末尾の `[3g]`・`(医療用)`・`(旧)` のようなかっこ書きと「」のあとの文字は外す。
- 成分規格（案） ＝ 成分＋剤形＋規格。需要のまとまり（案） ＝ 成分 ＋ 規格（錠・OD錠・口腔内崩壊錠・カプセル・徐放錠 などの飲む固形剤は同じまとまり。内用液・細粒・顆粒・外用は剤形を残して別のまとまり）。先発後発（案） ＝ 「屋号」があれば 後発。
- 確からしさ: 後発（屋号あり）／要確認：屋号なし（先発か旧名称。成分名で結ぶ）／要確認：剤形が読めない／要確認：規格が読めない。
- 同じまとまりの屋号数: 案が同じまとまりになった薬の数（2 以上は需要がかぶっている候補）。登録済みのまとまり: いまの手入力の値。未登録: 薬品グループ にない薬に ○。違い: 登録済みの値と案が違えば ○。
- 並び: 案が出た薬が先（まとまり → 薬品名）。
- **案は自動では使わない。** 人が確認して 薬品グループ に貼った値だけが区分とレポートに効く（2026-11-08 決定）。先発品（屋号なし）は成分名で手で結ぶ。塩の名前の違い（炭酸リチウム／リチウム炭酸塩）は別のまとまりになる。漢方・OTC・「徐放錠A」のような名前は要確認。
- 架空データ（tests/out）では 薬品グループ に 2 行（`アリピプラゾール錠3mg(旧)` の切替先 ＝ `アリピプラゾール錠3mg`、どちらも まとまり「アリピプラゾール 3mg」）を入れ、期待値は まとまり ごとに計算する（T_ABC月次 72 行、T_判定理由 50 件）。`tests/make_formats.py --check` は 薬品グループ案 も比べる。

## 3. レポートの定義

### R1 ABC 区分表（0.5 で区分 A／B／C／D に）

- 単位: 薬品グループの「需要のまとまり」。未登録の薬は薬品名単体。
- 窓: 出納のある月のうち直近「ABCの月数」ヶ月。その月までに出納か予定に一度でも出たまとまりは、窓に払出がなくても行を持つ（払出 0）。
- 月平均払出: 窓の払出のまとまりでの合計 ÷ 窓の月数（錠／月）。
- 量の区分: 月平均払出 ≧ 区分Aの線（1000）→ A、≧ 区分Bの線（300）→ B、それ未満 → C（0 も C）。固定の線なので、他の薬の増減で自分の区分は動かない。
- 患者の最少月: 窓の各月のうち予定データのある月について、まとまりの予定の延べ患者数（T_月次 の予定患者数をまとまりで合計。予定の行がない月は 0 人）を取り、そのいちばん少ない月の値。窓に予定データの月が 1 つもなければ空欄。月平均患者数は同じ月々の平均（参考）。
- 区分: 患者の最少月 ＜ 区分Dの患者数（2）→ D（量より優先。出納だけの薬は患者 0 なので D）。患者の最少月が空欄なら 量の区分。それ以外は 量の区分。
- 意味: A ＝ 一度に全量を発注できないほど需要が多い薬（在庫の上限を人が管理）、B ＝ 通常の発注量でよい薬、C ＝ 定期処方はあるが量は多くない薬、D ＝ 予定の患者が極端に少なく在庫を手で管理する薬。区分は持ち方を決めるだけで、返品・転送は区分と無関係。
- 構成比・累積: 窓の払出の構成比と累積。参考として残す（0.4 までの区分の根拠。区分には使わない）。
- 前月の区分: 終わりの月を 1 ヶ月前にずらして同じ計算。変更 = 「B→A」のように表示（変更なし）。
- 列: 需要のまとまり／薬品名／略称／先発後発／直近の払出／月平均払出／量の区分／患者の最少月／構成比／累積／今月の区分／前月の区分／変更／在庫日数／需要の型／最終在庫
- 月ごとの区分（T_ABC月次: 月×まとまり。列に 月平均払出・量の区分・患者の最少月・月平均患者数・区分・前月の区分・変更）も持ち、区分の安定性（K0 の ABC変更数）に使う。`bi/run.py` の `abc_monthly()` は `model.T_ABC月次` をそのまま返す。
- 線の初期値 1000／300／2 は仮の値。実データで M_薬品 の 月平均払出 と 直近の月平均患者数 の分布を見て決め直す。

### R2 不動薬の処理候補

- 対象: S01・S02・S05・S06 のいずれかが付いた薬。0.7 から、切替先 が入っている薬（切替元）も在庫 > 0 なら載せる。
- 余った量 = max(0, 最終在庫 − 直近の1日平均払出 × 当面の予定日数)。
- 列: 薬品名／略称／棚番／最終在庫／最後に動いた月／動きのない月数／在庫日数／直近の在庫日数／直近の1日平均払出／余った量／需要のまとまり／警告（S コードの文言）
- 並び: 動きのない月数の多い順、次に在庫日数の多い順。
- Power Pivot 版の B 表（⑯）: 種類 ＝ 不動／切替中／在庫過多（0.6.1 で「区分」から改名。区分 の列は M_薬品 の A／B／C／D）。切替元は 不動 とせず「切替中」とし、処置の案は「切替先「新品」の需要で使い切る（見込み N日）。返品できる分は返品」（N ＝ 切替の使い切り日数の切り上げ）。並びは 不動 → 切替中 → 在庫過多（`excel_format.ps1` で 不動 赤、切替中 黄色）。

### R3 経過措置・期限切迫

- 対象: 経過措置リストにある薬。
- 残り日数 = 経過措置期限 − 基準日（設定「発注日」）。期限切迫 = 残り日数 ≦ 期限切迫の日数。
- 期限までに使い切れる量 = 1日平均払出 × max(0, 残り日数)。余る量 = max(0, 最終在庫 − 使い切れる量)。
- 列: 薬品名／略称／経過措置期限／残り日数／期限切迫／最終在庫／1日平均払出／期限までに使い切れる量／余る量／警告（E01・E02）
- 並び: 残り日数の少ない順。
- 0.7 から: 代替の屋号 ＝ 薬品グループの 切替先 があればそれ、なければ同じ 需要のまとまり で経過措置のない薬（後発を優先、直近の払出の多い順）。切替先 が入っている薬の 1日平均払出 には まとまりの直近1日平均払出 を使う（旧品自身の払出は 0 に近いため）。使い切れる量・余る量もその値で計算する。

### R4 出荷調整の可能性

- G01: まとまり内の屋号ごとの月次構成比を出し、前月比の変化が線以上の屋号を月とともに出す。
- G02: 2.2 の条件。
- 列: 需要のまとまり／薬品名／月／コード／前月の構成比／当月の構成比／変化／まとまりの払出_前月／まとまりの払出_当月／理由
- 並び: 月の新しい順。

### R5 発注書（来週の分。0.6 で追加。Power Pivot 版は ㉔ R_発注書 → シート F_発注書）

週 1 回、発注する日に 発注日 を合わせて作る。`bi/run.py` の `r5_order()`（出力シート `R5_発注書`）。1 行 1 薬。

- 来週: 予測開始（発注日の翌日）～予測終了（予測開始 ＋ 予測日数 − 1。初期値 7 日）。
- 来週の予定・来週の患者: 予測データ（薬品使用量予測データ。予測フォルダパス、空欄なら実績フォルダ）の来週の 予定使用量・患者数 の合計。当月の予測データには月末までの予定が入っている。来週が翌月にかかるときは翌月のファイルも置く。
- 在庫: 予測データの一番新しい日の 在庫数量（発注残を含む）。予測データに出ない薬は M_薬品 の最終在庫（出納の最終月。月単位なので参考）。
- ずれ: M_薬品 の ずれの割合（1 年の 払出 ÷ 予定 − 1。空欄は 0）。見込み = 来週の予定 × max(0, 1 ＋ ずれ)。
- 不足 = max(0, 来週の予定 − 在庫)。発注の目安 = max(0, 見込み − 在庫) の切り上げ（錠。箱への切り上げは現場）。判定が「発注しない」なら 0。
- 必要な最大在庫: 1 年の日次の予定（T_日次）を「次の納品日」でまとめる。ある日の注文はその次の卸の営業日（④ fx_卸の休み：土日・祝日・年末年始・追加休業日を除く）に届くとし、同じ納品日になる日々を 1 つの区切りにして 予定数量 を合計、その最大 × max(0, 1 ＋ ずれ)。最大の期間 = その区切りの 最初の日～最後の日（日数）。連休をまたいでも不足しない在庫の上限の目安（区分 A の薬を人が管理するための数字）。棚の容積は入れない。
- 判定: 発注しない = 発注除外、または 供給状況 が 供給停止・薬価削除予定、または 切替元（薬品グループの 切替先 あり。0.7）。控えめに = 区分 D／経過措置品／供給状況 限定／ずれ ≦ −ずれの注意割合／切替先（0.7）のどれかで、目安 > 0。発注する = それ以外で 目安 > 0。不要 = 目安 0。経過措置品は「発注しない」ではなく「控えめに」。
- 注意（「、」でつなぐ）: 発注除外／供給停止・薬価削除予定／限定出荷／出荷調整の疑い（T_まとまり月次 の一番新しい月の G01・G02）／期限の近いロットを先に使う（T_ロット の 残り日数 ≦ 期限切迫の日数 か 返す量 > 0）／予定より n% 少なく出る／患者が少ない（区分 D）／経過措置品（切替先があれば発注しない）／予定にない薬（出どころ が 出納だけ）／上限を超える（区分 A で 在庫＋目安 ＞ 必要な最大在庫）／切替元（「新品」へ寄せる。在庫を使い切る）／切替先（切替元の在庫 N を使い切るまで控えめに）（0.7）。
- 載せる行: 来週の予定 > 0、不足 > 0、注意あり のいずれか、または 区分 A（常に）。
- 列: 区分／略称／薬品名／来週の予定／来週の患者／在庫／不足／ずれ／見込み／発注の目安／必要な最大在庫／最大の期間／判定／注意
- 並び: 区分（A→B→C→D→空欄）→ 略称 → 薬品名。
- 架空データ（tests/out）の期待値シート `R_発注書` は 薬品名・区分・来週の予定・来週の患者・在庫・不足・発注の目安・必要な最大在庫・判定 の列。ロット・出荷調整の注意だけで載る行は期待値に入れない。
- Python 版の訂正（0.6）: `bi/model.py` の `calendar()` が土曜を卸の営業日に数えていた。④ fx_卸の休み は最初から土曜を休みにしており、M 側は正しい。④ と同じ 追加休業日 → 祝日 → 年末年始 → 土曜 → 日曜 の順に直した。
