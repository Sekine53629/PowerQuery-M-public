## 1. 位置づけ

`bi/model.py` と `bi/run.py` は、Power Pivot 版（M クエリ ⓪～⑪ とピボット）と同じ入力から同じ表を作る Python 版です。
ここに書いた定義が正解で、Power Pivot 版はこの出力と一致するように直していきます。

- 入力: 実績フォルダ（薬品使用量予測データ YYYYMM）、出納フォルダ（数量一覧）、手入力テーブル.xlsx
- 出力: `bi/out/モデル.xlsx`（全テーブル）、`bi/out/ダッシュボード.html`
- 実行: `python bi/run.py --tables tests/out_clinic/export/手入力テーブル.xlsx`

データモデルの表（T_日次・T_月次・M_日付・M_薬品・M_理由コード・T_判定理由）は、M クエリ ⑥～⑪ の定義をそのまま写しています（列名・計算式とも同じ）。

## 2. 0.2.0 で Power Pivot 側に足すもの

### 2.1 M_薬品 に足す列（出納から）

| 列 | 定義 |
|---|---|
| 直近の払出合計 | 出納のある月のうち、新しい方から設定「直近の月数」（初期値 3）ヶ月の払出の合計 |
| 直近の1日平均払出 | 直近の払出合計 ÷ 直近の月の暦日数 |
| 直近の在庫日数 | 最終在庫 ÷ 直近の1日平均払出 |
| 直近の1箱消化日数 | 包装単位 ÷ 直近の1日平均払出 |

理由: 全期間の平均（在庫日数・1箱消化日数）は、途中で需要が落ちた薬を隠す。
架空データでは、出荷調整で切り替わったセルトラリン25「アメル」が、全期間平均では在庫 18 日分、直近では 1,066 日分になった。

## 3. レポートの定義

### R1 ABC 区分表

- 単位: 薬品グループの「需要のまとまり」。未登録の薬は薬品名単体。
- 払出: 出納のある月のうち直近「ABCの月数」ヶ月の払出をまとまりで合計。
- 区分: 払出の多い順に並べ、累積構成比 ≦ Aの線 → A、≦ Bの線 → B、それ以外 → C。
- 前月の区分: 終わりの月を 1 ヶ月前にずらして同じ計算。変更 = 「B→A」のように表示。
- 列: 需要のまとまり／薬品名／略称／先発後発／直近の払出／構成比／累積／今月の区分／前月の区分／変更／1箱消化日数／在庫日数／需要の型／最終在庫
- 月ごとの区分（T_ABC月次: 月×まとまり×区分）も持ち、区分の安定性（K0 の ABC変更数）に使う。

### R2 不動薬の処理候補

- 対象: S01・S02・S03・S05 のいずれかが付いた薬。
- 余った量 = max(0, 最終在庫 − 直近の1日平均払出 × 当面の予定日数)。返品できる箱数 = 余った量 ÷ 包装単位（切り捨て）。
- 列: 薬品名／略称／棚番／最終在庫／最後に動いた月／動きのない月数／在庫日数／直近の在庫日数／1箱消化日数／直近の1日平均払出／余った量／返品できる箱数／需要のまとまり／警告（S コードの文言）
- 並び: 動きのない月数の多い順、次に在庫日数の多い順。

### R3 経過措置・期限切迫

- 対象: 経過措置リストにある薬。
- 残り日数 = 経過措置期限 − 基準日（設定「発注日」）。期限切迫 = 残り日数 ≦ 期限切迫の日数。
- 期限までに使い切れる量 = 1日平均払出 × max(0, 残り日数)。余る量 = max(0, 最終在庫 − 使い切れる量)。
- 列: 薬品名／略称／経過措置期限／残り日数／期限切迫／最終在庫／1日平均払出／期限までに使い切れる量／余る量／警告（E01・E02）
- 並び: 残り日数の少ない順。

### R4 出荷調整の可能性

- G01: まとまり内の屋号ごとの月次構成比を出し、前月比の変化が線以上の屋号を月とともに出す。
- G02: 2.2 の条件。
- 列: 需要のまとまり／薬品名／月／コード／前月の構成比／当月の構成比／変化／まとまりの払出_前月／まとまりの払出_当月／理由
- 並び: 月の新しい順。

## 4. 統計（随時）

| No. | 内容 | 定義 |
|---|---|---|
| K0 月次サマリー | 月ごとに 1 行 | 払出合計／仕入合計／ロス量（その他の増減のマイナス分）／在庫数量合計（各薬の最後に載った在庫の合計）／動いた薬品数／不動薬の数と在庫（その月時点で「不動とみなす月数」以上動きがなく在庫あり）／予定患者数合計／ABC変更数／A・B・C の数 |
| K1 在庫日数の分布 | 帯ごとの薬品数と在庫数量 | 直近の在庫日数を 払出なし／～30／30～60／60～90／90～180／180～365／365日超 に分ける |
| K2 4 象限 | 需要の型 × 回転 | 回転は直近の1箱消化日数 ≧ 設定「1箱消化の注意日数」で「回らない」。薬品数と最終在庫の合計 |
| K4 ロス集計 | 月別と薬品別 | その他の増減のマイナス分（ロス）とプラス分（受け入れ） |
| K6 屋号の構成比 | まとまり×月×薬品 | 払出の構成比。屋号が 2 つ以上あるまとまりだけ |

- 出荷調整（セルトラリン25「アメル」→「トーワ」、2026/4）: R4 の G01 で 2026/4 に検出。アメルは S05（直近の在庫 1,066 日分）で R2 に出る。
- 経過措置（テトラミド、期限 2026/3/31）: R3 で E02（期限超過 184 日）、R2 で S01（4 ヶ月不動、在庫 386）。

## 6. 監視レポート（毎月見るもの。A4 横、`bi/report.py`）

毎月「何をすべきか」だけを載せる。各ページに目的の一文、KPI、見方、表（処置の案つき）。
出力は `bi/out/監視レポート.html` と `.pdf`（Edge のヘッドレス印刷）。追加の設定項目は 発注点の日数 7／発注量の日数 21／極小需要の箱数 1／転送候補の在庫日数 120／予測できるずれの線 0.5。

| 区分 | 目的 | 載せる行 | 主な列 | 処置の案の決め方 |
|---|---|---|---|---|
| A 発注点の切り替え提案 | 区分や払出が動いたまとまりの発注点を見直す | ABC の区分が前月から変わった、または直近 N ヶ月の払出が前の N ヶ月から ±20% 以上動いたまとまり | 区分（前→今）、直近／前の払出、変化、構成比、12 ヶ月の払出の棒、持ち方、発注点の目安、発注量の目安、理由 | 発注点 ＝ 直近の1日平均払出 × 発注点の日数。発注量 ＝ 発注量の日数分を包装単位に切り上げ。持ち方 ＝ 回転（直近の1箱消化日数 < 線）× 予測できる（ずれの大きさ < 線）の 4 区分 |
| B 不動在庫と転送・返品推奨 | 動かない在庫を返品・転送する | 在庫あり、かつ 不動（動きなし ≧ 線）または 在庫過多（直近の在庫日数 ≧ 線、または直近の払出 0） | 在庫の棒、最後に動いた月、動きなし、直近の在庫日数、余った量、返品できる箱、処置の案 | 不動で箱が残る → 返品。不動で端数 → 廃棄か転送。同じまとまりの別の屋号が動いている → 転送。それ以外 → 様子見（発注停止） |
| C 経過措置・期限切迫品 | 期限までに使い切れない在庫を早めに動かす | 経過措置リストの薬 | 期限、残り日数（帯）、在庫、1日平均払出、期限までに使い切れる量、余る量、処置の案（代替の屋号＝同じまとまりで経過措置のない後発を優先） | 期限超過 → 返品・廃棄・処方の切替確認。余る → 返品・転送と発注停止。使い切れる → 発注量を残り日数分に |
| D 出荷調整の管理票 | 推奨ジェネリックの入荷状況を見て切替・転送を決める | 屋号が 2 つ以上のまとまり（経過措置あり・疑いあり → 直近の払出の多い順、上限あり） | 役割（経過措置品を先に外し、残りの後発を直近の払出順に推奨・次点、先発、経過措置（管理継続））、直近の払出、構成比、在庫、直近の在庫日数、先月の仕入、状態（G01／G02）、12 ヶ月の構成比の積み上げ、切替・転送の案 | 推奨に G02 → 次点（なければ先発）へ切替。推奨の在庫 < 発注点の日数 → 次点を併用。G01 で構成比が落ちた屋号に在庫が残る → 転送・返品。経過措置品が一番出ている → 【警告】推奨を次点に置き換え（E04）。経過措置品の在庫は期限まで使い切れるか／余る量を示し、在庫 0 でも期限まで管理を継続 |
| E 要管理の極小需要薬 | 持つか取り寄せるかを決める | 直近 N ヶ月の払出が 月 1 箱以下（極小需要の箱数 × N 箱以下）の薬 | 需要の型、平均間隔、年間の予定患者数、直近の払出、在庫、直近の在庫日数、最後に動いた月、動いた月数、発注除外、処置の案 | 発注除外済み → そのまま。払出なし＋在庫あり → 返品・転送して発注除外へ。在庫なし → 取り寄せ。在庫日数 ≧ 線 → 1 箱だけ持ち余りは転送。それ以外 → 最低在庫 1 箱 |

注: 薬のロットの使用期限は出納・予測データに含まれない。在庫情報テーブルに「使用期限」列を足せば C に載せられる。
