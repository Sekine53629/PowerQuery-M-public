# PowerPivot_ABC_Analyze — inventory analysis

Read `../CLAUDE.md` first. Project-specific rules only.

## Goal
Psychiatric-clinic-adjacent pharmacy (tablets only). Keep the stock that avoids shortages while minimizing tied-up capital and waste. Outputs support dead-stock handling, returns, transfers to other stores, and near-expiry monitoring, plus the weekly order sheet F (0.6.0), a helper sheet proposing 薬品グループ entries from drug names and a 切替先 (switch-over) column for 経過措置 (0.7.0; since 0.8.0 the helper sheet lists only drugs that need grouping, in the hand table's column order). Since 0.9.0 the order sheet pools plan and stock over a 需要のまとまり and directs the group's order to one brand (発注先). Since 0.10.0 a trend (増加／減少／横ばい) computed from the ledger — last N months vs the N before vs the whole year — is shown in M_薬品, sheet A, sheet F and reason codes D07/D08; it never changes the order hint (the user adjusts). 0.10.1 fixes the proposal sheet's name parser (unit spellings such as ㎎, forms grouped by 変更調剤 substitution group). 0.11.0 adds a brand→ingredient table (㉖ 先発成分, from `src/_data/先発成分.csv`) so that 先発品 without a 「屋号」 land in the same まとまり as their generics, and teaches the parser the name patterns seen in the store's A–E output. Daily ordering is out of scope (separate tool PowerQuery_ABC).

## Layers (keep separate)
1. **Data**: facts only (T_日次, T_月次, M_日付, M_薬品 attributes + metrics). No judgments.
2. **EDA**: choosing metrics and thresholds. Done in Excel pivots / Python; conclusions go to `docs/`. Not a query.
3. **Judgment**: thresholds live in the settings table; results are emitted as reason codes with messages (T_判定理由). Always keep the reason.

## Data semantics (do not confuse)
- **薬品使用量分析データ (実績 folder) = PLAN.** Built from next-visit schedules: scheduled (定期) patients only; excludes ad-hoc/new/other-dept/skipped visits. Treat past dates as plan too. 患者数 = scheduled frequency only.
- **出納 monthly = ACTUAL.** Lists only drugs with any movement that month. No movement ⇒ stock unchanged, so current stock = 在庫数量 of the last month the drug appeared.
- 予定とのずれ = 払出 − 予定; can be + (ad-hoc, new, re-visits, dose up) or − (discontinued, leftover adjustment, no-show). Monthly sums cancel within a month (treat magnitude as a lower bound).
- Drugs unmoved since before the oldest loaded 出納 month appear nowhere (needs a full stock list once).
- No YJ code in the plan/ledger exports (the 不動品リスト does carry YJ/JAN codes and 薬価). Key = normalized drug name (出納: 品名). 略称 (column B) is display-only.
- 品名 in 出納 and in the three system lists starts with a mark: `劇 ` (劇薬), `向 ` (向精神薬), etc.; drugs without a mark start with 3 spaces. Queries strip the mark and leading spaces before matching (⑤ keeps it as 品名の記号). The plan file's 薬品名 has no mark.
- File names in this section show the `.xls` form the store exports today; since 0.4.0 every input may be `.xls/.xlsx/.csv/.txt` (see "Input formats").
- Three optional system lists (structure reports 2026-11-03), header row 1, data from row 2, no merged cells, newest file in the folder is read:

## Reference period and units (0.3.0)
- The settings table has no 開始日/終了日. `_shared/01_設定値` derives them: 終了日 = 予測開始 − 1 day (= 発注日 by default), 開始日 = first day of the month containing (終了日 − 1 year + 1 day). If a settings row 開始日/終了日 exists and is non-blank it wins (PowerQuery_ABC compatibility). ③ plan data and ⑤ 出納 both read only that window (⑤ keeps files whose period overlaps it).
- No pack size anywhere: no 包装単位 column, no 標準の包装単位, no 1箱消化日数/返品できる箱数. The only small-demand threshold is 極小需要の月の払出 (default 100), shared by ⑲ E, ⑬ G02 and ⑮ 持ち方 (回転 = 直近の1日平均払出 × 30 ≧ threshold). 発注量の目安 is plain days × per-day demand.

## Classification A/B/C/D (0.5.0)
- Decided 2026-11-08. The old ⑫ T_ABC月次 (per 需要のまとまり, last 3 ledger months, cumulative payout share ≤70% A, ≤90% B, else C) was relative — a drug's class moved when other drugs changed — and C was too wide to isolate "almost never dispensed" drugs. Replaced by fixed lines; 構成比／累積 columns remain as reference only.
- Meaning: **A** = demand too large to order in full at once (stock ceiling over holiday order gaps is managed by a person; keep A few). **B** = normal order quantities are fine. **C** = regular prescriptions but modest volume. **D** = extremely few scheduled patients, stock managed by hand (dead stock arises here). 区分 decides only how to hold stock; returns/transfers are independent of 区分.
- Rule (⑫, window = last 「ABCの月数」 (3) ledger months, per 需要のまとまり from the hand-entered 薬品グループ table read directly, not via M_薬品, so that ⑨ can reference ⑫): 量の区分 from 月平均払出 (錠/月): A ≥ 区分Aの線 (1000), B ≥ 区分Bの線 (300), else C (0 is C). 患者の最少月 = minimum over the window months that have plan data of the group's scheduled 延べ患者数 (T_月次 予定患者数 summed per group; a month without a plan row for the group counts as 0). 患者の最少月 < 区分Dの患者数 (2) → 区分 = D, overriding A/B/C (量の区分 is kept as a column so "D but 量 A" stays visible); ledger-only drugs get 0 → D; if the window has no plan month at all, 区分 = 量の区分. Every group seen in the ledger or plan up to that month gets a row each month even with 0 payout (a stopped drug stays D until it leaves the 1-year window). 前月の区分/変更 unchanged.
- No daily-dose master will be made (doses vary per patient); patient counts come from plan data only (the ledger has none). The EDA proposals "需要スコア" (log q + log p) and "偏った需要 D06" (`docs/EDA_*.md`) were not adopted; the D06 number is used for 区分 D.
- ⑨ M_薬品 new columns: 区分, 量の区分, 患者の最少月 (from ⑫'s latest month, joined by 需要のまとまり or 薬品名), 直近の月平均患者数 (average scheduled 延べ患者数 over the last 「ABCの月数」 plan months, per drug), 稼働四半期数 (number of the four 3-month quarters of the reading period with any scheduled patients; for spotting long-cycle patients). ⑮ A sheet: 量の区分, 月平均払出, 月平均患者数 after 区分変更; 今月の区分 may be D (grey in `tools/excel_format.ps1`). ⑲ E sheet: 区分 after 略称.
- Settings: `ABCのAの線 0.7`, `ABCのBの線 0.9` removed; `区分Aの線 1000`, `区分Bの線 300`, `区分Dの患者数 2` added; `ABCの月数 3` stays. Defaults apply if the rows are missing; old rows are ignored. The lines 1000/300/2 are provisional: tune after looking at the distribution of M_薬品 月平均払出 and 直近の月平均患者数 on real data.

## Order sheet F (0.6.0; pooling 0.9.0)
- ㉔ `R_発注書` (`src/24_R_発注書.m`), loaded as a table to sheet `F_発注書`; weekly. One row per drug; columns start 区分・略称・薬品名; sorted 区分 (A→B→C→D→blank) → 略称 → 薬品名 (0.9.0: pooled groups sort by the 発注先's 略称, see below). Autofilter on 区分 to print per class. 返品・転送 decisions stay independent of 区分.
- 来週の予定／来週の患者 = sum of 予定使用量／患者数 over 予測開始 (発注日 + 1) .. 予測終了 (予測開始 + 予測日数 − 1; default 7), read with ② from setting `予測フォルダパス`, or the 実績 folder when blank (the current month's 薬品使用量予測データ holds the whole month's schedule; when the week crosses into next month, next month's file must be present too).
- 在庫 = the newest day's 在庫数量 (発注残を含む) in the forecast data; drugs absent there use M_薬品 最終在庫 (ledger, month-level, reference only). ずれ = M_薬品 ずれの割合 (1 year, 払出÷予定 − 1; null → 0). 見込み = 来週の予定 × max(0, 1 + ずれ). 不足 = max(0, 来週の予定 − 在庫). 発注の目安 = ceil(max(0, 見込み − 在庫)) in tablets (box rounding by staff); 0 when 判定 = 発注しない.
- 必要な最大在庫: over the 1-year daily plan (T_日次), group days by "next delivery day" (an order placed on day d arrives on the first 卸の営業日 after d; 卸の営業日 from ④ fx_卸の休み: Sat/Sun, national holidays, 年末年始, 追加休業日), sum 予定数量 per block, take the maximum block, × max(0, 1 + ずれ). 最大の期間 shows that block's first～last plan day and day count. Meaning: the stock ceiling that avoids shortage over the longest delivery gap (for managing 区分 A by hand). Storage volume is deliberately NOT modelled.
- 判定: 発注しない = 発注除外 or 供給状況 ∈ {供給停止, 薬価削除予定}; 控えめに = (区分 D or 経過措置品 or 供給状況 限定 or ずれ ≤ −ずれの注意割合) and 目安 > 0; 発注する = otherwise and 目安 > 0; 不要 = 目安 0. 経過措置品 is 控えめに, not 発注しない. Since 0.9.0 the values are 発注する／控えめに／発注しない／寄せる／不要.
- 注意 (joined with 、): 発注除外／供給停止・薬価削除予定／限定出荷／出荷調整の疑い (⑬ latest month G01・G02)／期限の近いロットを先に使う (⑭ 残り日数 ≤ 期限切迫の日数 or 返す量 > 0)／予定より n% 少なく出る／患者が少ない（区分 D）／経過措置品（切替先があれば発注しない）／予定にない薬 (出どころ 出納だけ)／上限を超える（在庫＋目安 ＞ 必要な最大在庫; 区分 A only）.
- Rows shown: 来週の予定 > 0 or 不足 > 0 or 注意 ≠ "" or 区分 A (always).
- Settings added: `予測日数` 7, `予測フォルダパス` blank (blank → 実績フォルダ); defaults apply if the rows are missing. `tools/excel_install.ps1` creates the sheet; `tools/excel_format.ps1` formats it (widths, number formats; 判定 発注しない grey / 控えめに yellow; 注意 contains 上限を超える red; 発注の目安 ≥ 1 bold) and `-Pdf` includes F.
- 運用 (built txt): set 発注日 to the ordering day, refresh, print F_発注書; 発注しない drugs are not ordered even if short; 控えめに = less than the hint; 区分 A: split orders so stock stays below 必要な最大在庫.
- 0.7.0 additions: 切替元 (a drug whose 薬品グループ row has a 切替先) → 判定 発注しない, 注意 「切替元（「X」へ寄せる。在庫を使い切る）」; 切替先 (named as someone's 切替先) → 控えめに, 注意 「切替先（切替元の在庫 N を使い切るまで控えめに）」. Since 0.9.0 this wording applies only to switches that are not pooled (see next bullet).
- **0.9.0 pooling (発注の収束).** User request 2026-11-08: 「予測使用量の計算で、複数の品目が出てきており、グルーピング済みの品目であった場合の処理分岐を実装。需要量を合算し、発注量を算出」. When the hand table 薬品グループ puts ≥ 2 drugs (屋号) in the same 需要のまとまり, F sums 来週の予定 and 在庫 over the group (まとまりの予定, まとまりの在庫), computes 見込み・不足・発注の目安・必要な最大在庫 (and 上限を超える) from those sums with ずれ = M_薬品 まとまりのずれの割合, and shows them only on the row of the group's 発注先 (M_薬品 column, rule in the next section). The other brands' rows get 判定 「寄せる」, 発注の目安 0, blank 不足／見込み／必要な最大在庫／最大の期間, and 注意 「「<発注先>」に寄せる（まとまり「G」：予定 P・在庫 S を合算）」; the target row gets 注意 「まとまり「G」の発注先（n 品目の 予定 P・在庫 S を合算）」. Per-brand 来週の予定・来週の患者・在庫 keep each brand's own values. New columns 需要のまとまり・まとまりの予定・まとまりの在庫 after 在庫 (blank for unpooled drugs). Sort: 区分 → 発注先's 略称 → まとまり → 発注先 first → 薬品名, so a group's rows are listed together. Rows shown: group plan > 0 or group shortage > 0 or own notes (the pooling notes do not count) or 区分 A — when a group is listed, all its brands are. Drugs not in 薬品グループ, or alone in their まとまり, are computed per drug as before. A 切替先 inside a pooled group is no longer 控えめに for being a 切替先 (the 切替元's stock is already in the pooled stock); its note is 「切替先（切替元の在庫は合算済み）」 and the 切替元's is 「切替元（在庫を使い切る）」. `tools/excel_format.ps1`: 寄せる rows grey like 発注しない; まとまりの予定／まとまりの在庫 formatted `#,##0`. Reports A/B/C/E, reason codes and 区分 are unchanged in 0.9.0.
- **0.10.0 trend column.** New column 傾向 after ずれ: shows 増加／減少 only (blank for 横ばい／少量／月不足); for a pooled group it is M_薬品 まとまりの傾向, otherwise the drug's own 傾向. The row's 注意 gains 「減少傾向（直近 N ヶ月は前の N ヶ月の a%、年間の b%。患者は <患者の傾向>）。目安を減らすか検討」 or 「増加傾向（…）。目安を増やすか検討」 (N = setting 直近の月数; a = 前期比 × 100, b = 年間比 × 100; 患者の傾向 blank → 不明). **The 発注の目安 formula is unchanged** (来週の予定 × (1 + 年間のずれ) − 在庫); the user adjusts the quantity. A trend note alone does not make a row appear (載せる rule unchanged). `excel_format.ps1`: 傾向 増加 red fill, 減少 blue fill (same colours as A's 変化); width 6.

## Group proposal and switch-over (0.7.0; listing rule and column order 0.8.0; parser 0.10.1; brand table and store patterns 0.11.0)

- ㉕ `薬品グループ案` (`src/25_薬品グループ案.m`, loaded as a table to sheet `薬品グループ案`): one row per listed M_薬品 drug. Splits the name into 成分・剤形・規格・屋号 (generic names are `成分名＋剤形＋規格「屋号」`; trailing bracket notes `[3g]`, `(医療用)`, `(旧)` and text after `」` are dropped). 先発後発 = 後発 when a 「屋号」 exists, 先発 when the brand table resolves the name (0.11.0); 確からしさ ∈ {後発（屋号あり）, 先発（成分名で結んだ） (0.11.0), 要確認：屋号なし（先発か旧名称。成分名で結ぶ）, 要確認：剤形が読めない, 要確認：規格が読めない}. Parsing rule: next bullets.
- **Parser (0.10.1; `Parse` in ㉕).** Trigger 2026-11-09: the user ran 0.10.0 on the store's real drug names; ㉕ read no 規格 for most drugs (「規格が読み取れてません。μg mg ml 個 単位など表記が多岐にわたる」) and form grouping was weak (「カプセル 錠 OD錠 ザイディス などなど、グループ化するものも実装が少し甘い」). The 0.7.0 parser accepted only the characters `0-9 . m g μ µ L l % / 単 位` right after the first digit and knew few forms; % names parsed, mg names did not. Likely cause: single-character unit glyphs (㎎ ㎍ ㎖) and other spellings in the store's names — **inferred from the symptom, not confirmed by inspecting the characters** (real names are never copied out of the store).
  - Units: before parsing ㎎→mg, ㎍→μg, ㎖→mL, ㎕→μL, ㎏→kg, ㎜→mm, ㎝→cm, µ→μ (full-width ＭＧ etc. were already handled by fx_正規化); after reading, the unit is lower-cased and fixed (ml→mL, mcg/ug→μg, iu→IU, meq→mEq), so 25mg／25㎎／25MG all give 規格 25mg and the same まとまり.
  - 規格: every 「数字＋単位」 run in the name is collected (a digit preceded by a digit or 「.」 is not a new run, so 7.5 stays one number); unit characters after the number: ASCII letters, μ, %, /, 単, 位, 個, 万, 千 — so mg/mL, 単位, 万単位, 個 are read. The run with a unit is preferred; if none has a unit, the number right after the form is used (「錠7.5」→ 7.5). Examples: 「錠7.5 7.5mg」→ 7.5mg; 「1%点眼液 5mL」→ 1%; 「内用液1mg/mL」→ 1mg/mL; 「ビタミンB12錠500μg」→ 500μg with 成分 ビタミンB12.
  - 剤形 may be anywhere in the name (not only right before the number): the first form of the list (longest first) found in the name is used; 成分 = the text before the form or before the 規格 number, whichever comes first. Form list: 口腔内崩壊錠, フィルムコーティング錠, フィルムコート錠, チュアブル錠, ザイディス錠, ザイディス, 徐放カプセル, 徐放錠, 腸溶カプセル, 腸溶錠, 糖衣錠, 舌下錠, バッカル錠, ODフィルム, OD錠, D錠, CR錠, CRカプセル, SR錠, SRカプセル, LA錠, LAカプセル, ER錠, XR錠, R錠, 錠, ソフトカプセル, カプセル, フィルム, ドライシロップ, シロップ, 点眼液, 点鼻液, 吸入液, 外用液, 内用液, 液, 細粒, 顆粒, 散, 末, 丸, トローチ, テープ, パップ, ゲル, 軟膏, クリーム, ローション, 坐剤, 注.

## Trend (0.10.0)
- User decision 2026-11-08: 「予測は予測、実績をなるべく重きをおいて集計し、直近 3 ヶ月 vs その前 3 ヶ月 vs 年間の形で、傾向を分析し、発注量の調整をユーザーに委託する形が良い」 (earlier in the same conversation: 「増加傾向、減少傾向の傾向分析は、直近と年間の期ごとの動きの動態変化から予測する形にはしたい」). Consequences: the trend is computed from the ledger (実績) primarily, displayed with its reasons, and **never feeds 発注の目安** — the user adjusts the quantity.
- **Rule (⑨, per drug).** N = setting 直近の月数 (3). Compare 1-day average payouts of three windows: recent N ledger months, the N months before them, and all ledger months (年間). 前期比 = 直近の1日平均払出 ÷ previous-N 1日平均払出; 年間比 = 直近の1日平均払出 ÷ 1日平均払出 (all months). 傾向 ∈ {増加, 減少, 横ばい, 少量, 月不足}: 月不足 when the ledger has fewer than 2N months; 少量 when 月平均払出 < 極小需要の月の払出 (100) — sparse drugs are not judged; 増加 when both ratios ≥ 1 + 傾向の線 (new setting, default 0.2); 減少 when both ≤ 1 − 傾向の線; 横ばい otherwise. If the previous window is 0 and the recent one > 0 → 増加 (前期比 null).
- **⑨ M_薬品 new columns:** 前の払出合計 (payout of the N months before the recent N), 前期比, 年間比, 傾向; まとまりの前期比／まとまりの年間比／まとまりの傾向 (payouts summed over the 需要のまとまり, same rule; own values when unregistered — so an old→new switch shows as 横ばい for the group); 前の月平均患者数, 年間の月平均患者数 (with the existing 直近の月平均患者数, over plan months, window = ABCの月数), 患者の前期比, 患者の年間比, 患者の傾向 (same rule; 少量 when 年間の月平均患者数 < 区分Dの患者数 (2); 月不足 when plan months < 2 × ABCの月数); 直近のずれの割合 ((払出 − 予定) ÷ 予定 over the recent N months only — a patient who stopped coming shows here before it shows in the 1-year ずれ). ## Input formats (0.4.0)
- Accepted: `.xls/.xlsx/.csv/.txt(.tsv)`, may be mixed in one folder. ②⑤⑭⑳㉑㉓ open every file through ㉒ `fx_ファイルを開く(content, fileName, optional headerLabel)` (`_shared/22_fx_ファイルを開く.m`), which decides by content, not extension: bytes D0 CF 11 E0 → .xls, 50 4B → .xlsx, otherwise text. Returns シート名／Data／形式.
- Text files: encoding from BOM (UTF-8/UTF-16), else decode as UTF-8 and use 932 (Shift_JIS) if U+FFFD appears; delimiter = tab or comma, whichever is more frequent in the first 50 non-empty lines; column count from the longest line; all values text, blanks null.
- `headerLabel` (`"品名"` for 出納 and the three lists) returns only the sheets whose first 30 rows contain that header — `.xls` sheets arrive sorted by name, so "first sheet" means nothing.
- Errors: an empty file, content starting with `<` (HTML/XML saved as .xls) or any open failure raises a named error (`[読めないファイル] 「<file>」を開けません：…`). ⑤⑭⑳㉑ raise the same kind of error when a file in the reading window has no 品名 header row (no silent skip). ② still skips a sheet without a 薬品名 header.
- Plan data (②) in text files has no sheets, so one of two shapes is read, otherwise the file is not read: (1) a header column `日付` (label fixed in ①), any number of days per file; (2) one file per day with an 8-digit date in the file name (`薬品使用量分析データ20261010.csv`). **Provisional: the real エリシアS CSV layout of this report is not confirmed.**
- 出納 and the lists in text files: same header names as the .xls (header row found by 品名); 出納's in-file period lines above the header still work.
- Number conversion (②⑤⑭⑳㉑): remove spaces, thousands separators, yen marks; ▲/△ → minus; `Number.FromText`, else the leading numeric part (`1,234`, `100錠`, `¥9,801`, `▲50`, `12.5%`). - Codes are permanent (never renumber/reuse; retire as 欠番 — keep the row in ⑩ with 種類 "欠番", never emit it in ⑪). Retired: S03 (0.3.0, pack-based). Prefixes: S stock/dead, D demand, P plan gap, E expiry/regulatory, Q data quality, J final verdict (not implemented).
- D06 (0.5.0, 需要/注意): 「予定の患者が月 {値}人しかいません。（線 {線}人）区分 D：在庫は手で管理する薬です」, emitted in ⑪ when M_薬品 区分 = D and 出どころ ≠ 出納だけ (値 = 患者の最少月, 線 = 区分Dの患者数; ledger-only drugs keep Q01; a 切替元 gets E05 instead, not D06).
- E05 (0.7.0, 期限・制度/注意): 「切替元です。在庫 {在庫} は切替先の需要で {値}日で使い切る見込みです。返品できる分は返品してください。」, emitted for a drug with a 切替先 (値 = 切替の使い切り日数). E06 (0.7.0, 期限・制度/注意): 「切替先です。切替元の在庫 {値} がなくなるまで、発注は控えめにしてください。」, emitted for a drug named as someone's 切替先 (値 = 切替元の在庫).
- D07 (0.10.0, 需要/注意/2): 「増加傾向です。直近の払出は前の期の {値}%、年間の {線}% です。発注量を増やす余地を見てください。」, emitted when M_薬品 傾向 = 増加. D08 (0.10.0, 需要/注意/2): 「減少傾向です。直近の払出は前の期の {値}%、年間の {線}% です。発注量を減らすことを考えてください。」, emitted when 傾向 = 減少. 値 = 前期比 × 100, 線 = 年間比 × 100; the drug's own 傾向, not the group's (see "Trend").
