# PowerPivot_ABC_Analyze — inventory analysis

Read `../CLAUDE.md` first. Project-specific rules only.

## Goal
Psychiatric-clinic-adjacent pharmacy (tablets only). Keep the stock that avoids shortages while minimizing tied-up capital and waste. Outputs support dead-stock handling, returns, transfers to other stores, and near-expiry monitoring, plus the weekly order sheet F (0.6.0). Daily ordering is out of scope (separate tool PowerQuery_ABC).

## Layers (keep separate)
1. **Data**: facts only (T_日次, T_月次, M_日付, M_薬品 attributes + metrics). No judgments.
2. **EDA**: choosing metrics and thresholds. Done in Excel pivots / Python; conclusions go to `docs/`. Not a query.
3. **Judgment**: thresholds live in the settings table; results are emitted as reason codes with messages (T_判定理由). Always keep the reason.

## Data semantics (do not confuse)
- **薬品使用量分析データ (実績 folder) = PLAN.** Built from next-visit schedules: scheduled (定期) patients only; excludes ad-hoc/new/other-dept/skipped visits. Treat past dates as plan too. 患者数 = scheduled frequency only.
- **出納 monthly = ACTUAL.** Lists only drugs with any movement that month. No movement ⇒ stock unchanged, so current stock = 在庫数量 of the last month the drug appeared.
- 予定とのずれ = 払出 − 予定; can be + (ad-hoc, new, re-visits, dose up) or − (discontinued, leftover adjustment, no-show). Monthly sums cancel within a month (treat magnitude as a lower bound).
- Drugs unmoved since before the oldest loaded 出納 month appear nowhere (needs a full stock list once).
- No YJ code in the plan/ledger exports (the 不動品リスト does carry YJ/JAN codes and 薬価). Key = normalized drug name (出納: 品名). 略称 (column B) is display-only.
- 品名 in 出納 and in the three system lists starts with a mark: `劇 ` (劇薬), `向 ` (向精神薬), etc.; drugs without a mark start with 3 spaces. Queries strip the mark and leading spaces before matching (⑤ keeps it as 品名の記号). The plan file's 薬品名 has no mark.
- File names in this section show the `.xls` form the store exports today; since 0.4.0 every input may be `.xls/.xlsx/.csv/.txt` (see "Input formats").
- Three optional system lists (structure reports 2026-11-03), header row 1, data from row 2, no merged cells, newest file in the folder is read:
  - `経過措置薬品リスト.xls` (経過措置フォルダパス): per drug. A 記号 (× = stock 0), B 製剤コード, C 製剤, D コード, E 品名, F メーカーコード, G メーカー, H 経過措置 (date), I 在庫数量, J 単位.
  - `YYYYMMDD_期限切れリスト.xls` (期限切迫フォルダパス): per purchase-slip line (lot). 26 columns incl. E 品名, H 棚番, I 伝票日付, N 仕入先, P 仕入数量, Q 単価, R 期限, S 期限切れ数量, T 単位, V ロット番号.
  - `YYYYMM_不動品リスト.xls` (不動品フォルダパス): per purchase-slip line (lot). 42 columns incl. E 品名, H 棚番, R 期限日, S 最終払出日, Z 数量, AA 単位, AC 薬価, AH ロット番号, AJ 基準日, AK 最終使用日, AL 不動日数, AM YJコード, AO JANコード.
- 出納 file: `yyyymmdd_yyyymmdd_数量一覧.xls`, one sheet, 10 fixed columns. Header row = the row containing 品名; rows above it may carry 出力日/期間. Period = first in-file date pair (前 ≦ 後) above the header, else the two 8-digit numbers in the file name. Real-file layout above the header is not yet confirmed with a sample. Analysis-data file (real name `薬品使用量予測データYYYYMM.xls`): prefix `薬品使用量`, daily sheets `10月1日(水)`, header row 1 merged with blank row 2, data from row 3. ## Reference period and units (0.3.0)
- The settings table has no 開始日/終了日. `_shared/01_設定値` derives them: 終了日 = 予測開始 − 1 day (= 発注日 by default), 開始日 = first day of the month containing (終了日 − 1 year + 1 day). If a settings row 開始日/終了日 exists and is non-blank it wins (PowerQuery_ABC compatibility). ③ plan data and ⑤ 出納 both read only that window (⑤ keeps files whose period overlaps it).
- No pack size anywhere: no 包装単位 column, no 標準の包装単位, no 1箱消化日数/返品できる箱数. The only small-demand threshold is 極小需要の月の払出 (default 100), shared by ⑲ E, ⑬ G02 and ⑮ 持ち方 (回転 = 直近の1日平均払出 × 30 ≧ threshold). 発注量の目安 is plain days × per-day demand.

## Classification A/B/C/D (0.5.0)
- Decided 2026-11-08. The old ⑫ T_ABC月次 (per 需要のまとまり, last 3 ledger months, cumulative payout share ≤70% A, ≤90% B, else C) was relative — a drug's class moved when other drugs changed — and C was too wide to isolate "almost never dispensed" drugs. Replaced by fixed lines; 構成比／累積 columns remain as reference only.
- Meaning: **A** = demand too large to order in full at once (stock ceiling over holiday order gaps is managed by a person; keep A few). **B** = normal order quantities are fine. **C** = regular prescriptions but modest volume. **D** = extremely few scheduled patients, stock managed by hand (dead stock arises here). 区分 decides only how to hold stock; returns/transfers are independent of 区分.
- Rule (⑫, window = last 「ABCの月数」 (3) ledger months, per 需要のまとまり from the hand-entered 薬品グループ table read directly, not via M_薬品, so that ⑨ can reference ⑫): 量の区分 from 月平均払出 (錠/月): A ≥ 区分Aの線 (1000), B ≥ 区分Bの線 (300), else C (0 is C). 患者の最少月 = minimum over the window months that have plan data of the group's scheduled 延べ患者数 (T_月次 予定患者数 summed per group; a month without a plan row for the group counts as 0). 患者の最少月 < 区分Dの患者数 (2) → 区分 = D, overriding A/B/C (量の区分 is kept as a column so "D but 量 A" stays visible); ledger-only drugs get 0 → D; if the window has no plan month at all, 区分 = 量の区分. Every group seen in the ledger or plan up to that month gets a row each month even with 0 payout (a stopped drug stays D until it leaves the 1-year window). 前月の区分/変更 unchanged.
- No daily-dose master will be made (doses vary per patient); patient counts come from plan data only (the ledger has none). The EDA proposals "需要スコア" (log q + log p) and "偏った需要 D06" (`docs/EDA_*.md`) were not adopted; the D06 number is used for 区分 D.
- ⑨ M_薬品 new columns: 区分, 量の区分, 患者の最少月 (from ⑫'s latest month, joined by 需要のまとまり or 薬品名), 直近の月平均患者数 (average scheduled 延べ患者数 over the last 「ABCの月数」 plan months, per drug), 稼働四半期数 (number of the four 3-month quarters of the reading period with any scheduled patients; for spotting long-cycle patients). ⑮ A sheet: 量の区分, 月平均払出, 月平均患者数 after 区分変更; 今月の区分 may be D (grey in `tools/excel_format.ps1`). ⑲ E sheet: 区分 after 略称.
- Settings: `ABCのAの線 0.7`, `ABCのBの線 0.9` removed; `区分Aの線 1000`, `区分Bの線 300`, `区分Dの患者数 2` added; `ABCの月数 3` stays. Defaults apply if the rows are missing; old rows are ignored. The lines 1000/300/2 are provisional: tune after looking at the distribution of M_薬品 月平均払出 and 直近の月平均患者数 on real data.
- Planned next (order changed 2026-11-08: the order sheet F came first as 0.6.0): 0.7.0 経過措置 switch-over (旧品→新品: 切替先 column in 薬品グループ, old → D, successor inherits the group's class, E05/E06); then two-stage refresh for speed. Tuning the three 区分 lines on real data stays the first item.

## Order sheet F (0.6.0)
- ㉔ `R_発注書` (`src/24_R_発注書.m`), loaded as a table to sheet `F_発注書`; weekly. One row per drug; columns start 区分・略称・薬品名; sorted 区分 (A→B→C→D→blank) → 略称 → 薬品名. Autofilter on 区分 to print per class. 返品・転送 decisions stay independent of 区分.
- 来週の予定／来週の患者 = sum of 予定使用量／患者数 over 予測開始 (発注日 + 1) .. 予測終了 (予測開始 + 予測日数 − 1; default 7), read with ② from setting `予測フォルダパス`, or the 実績 folder when blank (the current month's 薬品使用量予測データ holds the whole month's schedule; when the week crosses into next month, next month's file must be present too).
- 在庫 = the newest day's 在庫数量 (発注残を含む) in the forecast data; drugs absent there use M_薬品 最終在庫 (ledger, month-level, reference only). ずれ = M_薬品 ずれの割合 (1 year, 払出÷予定 − 1; null → 0). 見込み = 来週の予定 × max(0, 1 + ずれ). 不足 = max(0, 来週の予定 − 在庫). 発注の目安 = ceil(max(0, 見込み − 在庫)) in tablets (box rounding by staff); 0 when 判定 = 発注しない.
- 必要な最大在庫: over the 1-year daily plan (T_日次), group days by "next delivery day" (an order placed on day d arrives on the first 卸の営業日 after d; 卸の営業日 from ④ fx_卸の休み: Sat/Sun, national holidays, 年末年始, 追加休業日), sum 予定数量 per block, take the maximum block, × max(0, 1 + ずれ). 最大の期間 shows that block's first～last plan day and day count. Meaning: the stock ceiling that avoids shortage over the longest delivery gap (for managing 区分 A by hand). Storage volume is deliberately NOT modelled.
- 判定: 発注しない = 発注除外 or 供給状況 ∈ {供給停止, 薬価削除予定}; 控えめに = (区分 D or 経過措置品 or 供給状況 限定 or ずれ ≤ −ずれの注意割合) and 目安 > 0; 発注する = otherwise and 目安 > 0; 不要 = 目安 0. 経過措置品 is 控えめに, not 発注しない.
- 注意 (joined with 、): 発注除外／供給停止・薬価削除予定／限定出荷／出荷調整の疑い (⑬ latest month G01・G02)／期限の近いロットを先に使う (⑭ 残り日数 ≤ 期限切迫の日数 or 返す量 > 0)／予定より n% 少なく出る／患者が少ない（区分 D）／経過措置品（切替先があれば発注しない）／予定にない薬 (出どころ 出納だけ)／上限を超える（在庫＋目安 ＞ 必要な最大在庫; 区分 A only）.
- Rows shown: 来週の予定 > 0 or 不足 > 0 or 注意 ≠ "" or 区分 A (always).
- Settings added: `予測日数` 7, `予測フォルダパス` blank (blank → 実績フォルダ); defaults apply if the rows are missing. `tools/excel_install.ps1` creates the sheet; `tools/excel_format.ps1` formats it (widths, number formats; 判定 発注しない grey / 控えめに yellow; 注意 contains 上限を超える red; 発注の目安 ≥ 1 bold) and `-Pdf` includes F.
- 運用 (built txt): set 発注日 to the ordering day, refresh, print F_発注書; 発注しない drugs are not ordered even if short; 控えめに = less than the hint; 区分 A: split orders so stock stays below 必要な最大在庫.

## Input formats (0.4.0)
- Accepted: `.xls/.xlsx/.csv/.txt(.tsv)`, may be mixed in one folder. ②⑤⑭⑳㉑㉓ open every file through ㉒ `fx_ファイルを開く(content, fileName, optional headerLabel)` (`_shared/22_fx_ファイルを開く.m`), which decides by content, not extension: bytes D0 CF 11 E0 → .xls, 50 4B → .xlsx, otherwise text. Returns シート名／Data／形式.
- Text files: encoding from BOM (UTF-8/UTF-16), else decode as UTF-8 and use 932 (Shift_JIS) if U+FFFD appears; delimiter = tab or comma, whichever is more frequent in the first 50 non-empty lines; column count from the longest line; all values text, blanks null.
- `headerLabel` (`"品名"` for 出納 and the three lists) returns only the sheets whose first 30 rows contain that header — `.xls` sheets arrive sorted by name, so "first sheet" means nothing.
- Errors: an empty file, content starting with `<` (HTML/XML saved as .xls) or any open failure raises a named error (`[読めないファイル] 「<file>」を開けません：…`). ⑤⑭⑳㉑ raise the same kind of error when a file in the reading window has no 品名 header row (no silent skip). ② still skips a sheet without a 薬品名 header.
- Plan data (②) in text files has no sheets, so one of two shapes is read, otherwise the file is not read: (1) a header column `日付` (label fixed in ①), any number of days per file; (2) one file per day with an 8-digit date in the file name (`薬品使用量分析データ20261010.csv`). **Provisional: the real エリシアS CSV layout of this report is not confirmed.**
- 出納 and the lists in text files: same header names as the .xls (header row found by 品名); 出納's in-file period lines above the header still work.
- Number conversion (②⑤⑭⑳㉑): remove spaces, thousands separators, yen marks; ▲/△ → minus; `Number.FromText`, else the leading numeric part (`1,234`, `100錠`, `¥9,801`, `▲50`, `12.5%`). Date reading (②⑭⑳㉑): date cells, `yyyy/mm/dd`, `yyyy-mm-dd`, `yyyy年m月d日`, 8-digit `yyyymmdd`, text with a time part.
- ㉓ `読込の確認` (`src/23_読込の確認.m`, loaded to sheet `読込の確認`): row 1 = reading period (開始日～終了日, 発注日); then one row per file in each of the five folders (実績／出納／期限切れリスト／経過措置薬品リスト／不動品リスト) with 種類, ファイル名, 更新日時, 形式, シート数, 見出しの行, 行数, 結果. 結果 = `読める…` / `読まない：…` (not a target: wrong name or extension, outside the period, a newer list exists, no date for a text plan file) / `読めない：…` (cannot open, no header), each with the reason. When numbers are missing, look here first; at the store, this sheet's content is what gets reported.
- `bi/model.py` (Python reference) follows the same rules: `open_tables()` / `first_table()` / `list_files()`, `.xls` via xlrd. Since 0.5.0 it also builds `T_ABC月次` (`abc_table()`, before M_薬品) with `DEFAULTS` 区分Aの線/区分Bの線/区分Dの患者数; `bi/run.py` `abc_monthly()` returns `model.T_ABC月次`, R1 carries 月平均払出/量の区分/患者の最少月, K0 counts D; `bi/report.py` page A shows A/B/C/D counts. Since 0.6.0: `Settings.fc_start/fc_end/fc_folder`, `DEFAULTS` 予測日数=7, `load_plan(..., keep_zero=True)`, `Model.予測データ`; `bi/run.py` `r5_order()` → output sheet `R5_発注書`; `bi/report.py` `page_f`. Correction of the Python reference only (M ④ was already right): `calendar()` used to count Saturday as a wholesaler business day; now Saturday is a non-delivery day like ④, reason order 追加休業日 → 祝日 → 年末年始 → 土曜 → 日曜.

| T_日次 | date × drug | 日付, 薬品名 |
